# knowledge-html

初心者でも見た瞬間に構造がわかる、読み物型の知識HTMLを保存・公開するリポジトリです。

## 基本ルール

- 各テーマは `slug/index.html` を公開起点にします。
- CSS / JavaScript / metadata は同じテーマフォルダ内に置きます。
- 本格Webアプリは別リポジトリで管理し、このリポジトリは「読むための知識HTML」専用です。
- 検索・再発見は Second Brain Bridge を入口にする前提です。
- 結論 → 全体像 → 詳細の順で構成します。
- LEVEL 1（30秒）→ LEVEL 2（3〜5分）→ LEVEL 3（詳細）の3層構造を基本とします。
- 長文をそのまま置かず、比較表・フロー・カード・図解・アコーディオン等へ変換します。
- 難しい内容は削除せず、分解・言い換え・図解・階層化します。
- 専門用語・数値・条件・例外・コードは保持します。
- PC / iPhone / iPadで閲覧できるレスポンシブ設計にします。

## 音声読み上げ標準

ブラウザの Speech Synthesis API を利用できる場合、以下を標準実装します。

- ページ上部に「要点を聞く」ボタン。
- 必要に応じて各章に「この章を聞く」ボタン。
- 「読み上げ停止」ボタン。
- 読み上げ速度をユーザーが変更できるUI。
- 速度範囲: **0.7×〜3.0×**。
- 基本刻み: **0.1**。
- 初期値: **1.0×**。
- 選択した速度は `localStorage` 等で端末に保存し、次回表示時にも引き継ぎます。
- 速度は色だけで示さず、数値（例: `1.4×`）でも表示します。
- スマホでは速度調整UIが横幅を圧迫しないレスポンシブ設計にします。

### 日本語・英語混在時

- 日本語部分と英語部分を自動判定し、同じ日本語音声で全体を読ませない。
- 日本語は原則 `ja-JP`、英語は原則 `en-US` または `en-GB` を使う。
- 英語で書かれた語句・英文は、日本語音声によるカタカナ英語にしない。
- 日本語と英語で、女性声と男性声が混在するなど声質が大きく変わらないよう、両言語で同じ声質プロファイルを優先する。
- 現在の標準プロファイルは女性寄り。Speech Synthesis APIには標準の性別情報がないため、既知の音声名や声質傾向をヒントに選択し、完全一致を前提にしない。
- 端末に複数の音声がある場合は、`Natural` / `Neural` / `Premium` / `Enhanced` 等の自然音声を優先する。ただし声質統一を崩す場合は同系統の声を優先する。
- 長文は文・意味のまとまりで短く分割し、読み上げの詰まりや不自然な抑揚を減らす。
- 絵文字・矢印など、読み上げると邪魔になる装飾文字は音声用テキストから除外または自然な区切りへ変換する。
- 英語教材では英文要素へ可能な限り `lang="en"`、日本語解説へ `lang="ja"` を付け、自動判定と併用する。
- 必要に応じ「全文を聞く」「英文だけ聞く」「日本語解説だけ聞く」を実装する。
- 略語・固有名詞・多義語など誤読しやすい語には発音辞書または音声用テキストを用意できる設計にする。
- ブラウザやOSによって利用可能な音声が異なるため、特定の音声名へ固定せず、その端末で利用可能な最適候補を選ぶ。

## Second Brain Bridge連携

ルートの `registry.json` に各HTMLのメタデータを登録し、Second Brain Bridgeはこのカタログを読み取り専用で検索します。

- GitHub = 保存・公開する場所
- Second Brain Bridge = 探す場所
