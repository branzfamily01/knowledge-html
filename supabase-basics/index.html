PostgreSQL（ポストグレスキューエル）
Supabaseの中心にあるオープンソースのリレーショナルデータベース。Supabaseでは各プロジェクトにPostgresデータベースが用意されます。
重要
🚪 アプリとSupabaseが話すための窓口

プログラム同士が決められた方法でデータや機能をやり取りするための接点です。
重要

Auth / Authentication（認証）
ユーザーのログイン状態や本人確認を扱う仕組みです。
必須
🛡️ 「この人には、このデータだけ」を決める門番
RLS / Row Level Security
PostgreSQLの行単位アクセス制御。SupabaseのData APIで公開されるテーブルを守る重要な仕組みです。

安全性で最低限覚える3つ

必須

Publishable key

sb_publishable_...

ブラウザやモバイルアプリなど、公開されるクライアントで使うことを想定した低権限キーです。

危険・NG

Secret key

sb_secret_...

HTMLや公開JavaScriptに入れない。 バックエンド専用です。旧 service_role も同じ考え方です。

注意

RLSを設定する

「キーが公開されているから危険」ではなく、公開クライアントからのアクセスをRLSと権限設定で制御するのが重要です。

LEVEL 3｜しっかり理解

コードで見ると何をしている？

発展

まず意味：Supabaseの「住所」と「公開用の接続キー」を渡して、接続役を作る

Supabase URL
プロジェクトの住所
＋
Publishable key
公開クライアント用キー
→
Supabase Client
コードを見る 
import { createClient } from '@supabase/supabase-js'

const supabase = createClient(
  SUPABASE_URL,          // SupabaseプロジェクトのURL
  SUPABASE_PUBLISHABLE_KEY // 公開クライアント用キー
)

重要：このコードに sb_secret_... や旧 service_role を入れてはいけません。

発展

RLSは「データを取るたびに働くルール」

たとえば、ユーザーIDが一致する行だけ読めるようにすれば、同じテーブルの中に複数ユーザーのデータがあっても、自分の行だけを取得する設計にできます。

create policy "Users can read their own rows"
on learning_history
for select
to authenticated
using ((select auth.uid()) = user_id);

これはイメージとして、すべての検索に「自分の user_id の行だけ」という条件が自動で付くようなものです。

注意

「Supabaseを入れた＝自動的に安全」ではない

Supabaseは安全に作るための仕組みを提供しますが、RLS・権限・キーの使い分けを間違えると危険です。公開されるテーブルでは、RLSと必要最小限の権限設定を確認します。

補足：昔の anon / service_role という名前は？

Supabaseでは現在、クライアント側は Publishable key、バックエンド側は Secret key が新しい方式です。

旧 anon はPublishable keyに近い低権限側、旧 service_role はSecret keyに近い強い権限側です。新規設計では新しいキー方式を優先します。

10秒理解チェック

全部覚える必要はありません。「説明できそうか」だけ確認します。

Q1. GitHub PagesとSupabaseの一番大きな役割の違いは？

GitHub Pagesは主にWebページ・画面を公開する場所。Supabaseはデータベースやログインなど、アプリの裏側を担当します。

Q2. Supabaseの中心にあるデータベースは？

PostgreSQL（Postgres）です。

Q3. sb_secret_... をHTMLに書いてよい？

NGです。Secret keyや旧service_roleはブラウザへ公開せず、信頼できるバックエンドでだけ使います。

Q4. RLSを一言でいうと？

「誰が、どの行のデータを読んだり変更したりできるか」をデータベース側で決める門番です。

最後に、もう一度だけ

Supabase ＝ Webアプリの「裏側」を作りやすくするサービス。

まずは「GitHub Pagesは画面を公開、Supabaseはデータやログインを担当」と覚えれば十分です。必要になったらPostgres・Auth・RLSへ一段ずつ降りて理解すればOKです。
